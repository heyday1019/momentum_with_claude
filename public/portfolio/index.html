Auth · Onboarding

3채널 로그인 + onboarding 게이트

  • Kakao OAuth — 한국 메인 채널
  • Google OAuth — 데스크톱·외국
  • Email Magic Link — 비밀번호 없음
  • → /auth/callback에서 PKCE code 교환
  • → profile 없으면 /onboarding으로 강제 이동
  • → proxy.ts가 매 요청마다 session refresh
// src/proxy.ts (Next 16 convention)
export async function proxy(req: NextRequest) {
  const { supabase, response } = createMiddleware(req)
  const { data: { user } } = await supabase.auth.getUser()

  const isProtected = PROTECTED_PATHS
    .some(p => req.nextUrl.pathname.startsWith(p))

  if (isProtected && !user) {
    return NextResponse.redirect(
      new URL('/login', req.url)
    )
  }
  return response
}

// 'use server'
export async function setTheme(theme: Theme) {
  const store = await cookies()
  store.set('theme', theme, {
    httpOnly: true,
    sameSite: 'lax',
    maxAge: 60 * 60 * 24 * 365,
  })
  revalidatePath('/', 'layout')
}

Lessons learned

비자명했던 결정들

🔧 Supabase eq-chain quirk
BAD .select('content').eq().eq().eq().maybeSingle() — single column projection + 다중 eq + maybeSingle 조합에서 row가 있어도 0 rows 반환하는 케이스 발견. GOOD .match({...}).limit(1) + data[0] 패턴으로 통일.
🤖 OpenRouter Claude의 ```json 펜스 응답
BAD response_format: json_object를 줘도 anthropic/claude-haiku는 ``` 코드펜스로 감싸 반환 → JSON.parse 실패. GOOD parseJsonLoose 헬퍼 — 펜스 strip 후 파싱, 모든 LLM 응답에 적용.
🔀 Next 16 file convention 변경
BAD middleware.ts는 Next 16에서 deprecated. GOOD src/proxy.ts + export function proxy()로 리네임. helper는 middleware.ts 이름 유지 (함수 vs 컨벤션 분리).
🖼 satori는 transform을 지원하지 않는다
BAD 역방향 타로 카드 OG 이미지에 rotate(180deg) 적용 → satori가 무시. GOOD 점선 테두리 + "역방향" chip 라벨로 시각적 구분.
🔌 AI 호출 ↔ DB 로깅의 의존성 역전
OpenRouter client가 Supabase에 직접 import하면 단위 테스트에서 mock 지옥. GOOD onUsage 콜백으로 의존성 역전 — client는 토큰 카운트만 알고, Supabase 저장은 caller가 결정.
